# PixVault for Windows アプリ仕様書 v0.7.2

更新日: 2026-09-14。対象: Windows 10/11 x64。以下以外はv0.7.1の仕様を継承する。過去版の成果物・仕様書は保持する。

## ネイティブ動画の表示領域

- WindowsのlibVLC映像は、WebView内の透明canvasを位置合わせ用アンカーとして使い、ネイティブの子ウィンドウへ直接描画する。
- 子ウィンドウの位置と大きさはcanvas固有の300×150比率や一時的なレイアウト値ではなく、`.pv-video-surface`全体の実寸から算出する。
- canvasは動画面の左上へ絶対配置し、幅・高さを100%にする。動画切替直後やウィンドウ再配置中もcanvasの固有寸法をグリッド計算へ混入させない。
- オーバーフローする祖先、操作バー、モーダル等の非表示領域は、動画面の実寸を基準に従来どおりネイティブ描画から除外する。
- 指定された問題動画のメタデータは1280×720、29.97fpsであり、元ファイルの縦横比変更や変換は行わない。

## ビュワーの前後移動

- メディア表示領域の左端12%（56～120px）を450ms以内、移動14px以内でタップすると前のメディアへ移動する。右端も同条件で次へ移動する。
- 先頭で前、末尾で次を操作した場合は移動せず、端から端への循環はしない。
- ボタン、入力欄、リンク、メニュー等から始まる操作は端タップ判定から除外する。ドラッグ、複数ポインター、長押しもメディア移動として確定しない。
- 端タップを確定した場合は、同じ入力による動画の再生／停止やダブルタップシークを抑止する。動画面中央の単タップによる再生／停止、左右半分のダブルタップによるシークは維持する。
- 入力欄、ボタン、リンク、メニュー等へフォーカスしていないとき、左キーで前、右キーで次のメディアへ移動する。画像、GIF、動画、ブックで共通とする。
- 全メディア一覧の遅延読込中は要求番号と移動元を照合し、古い読込結果で現在表示を上書きしない。
- ブックのページ移動は画面上のページボタン、PageUp／PageDown、Home／Endおよびシークバーを使用する。左右キーは他形式と同じメディア間移動に割り当てる。

## 確認方法と未確認事項

CLIと合成データを使ったヘッドレスChromiumで、動画面とcanvasの寸法不一致、ネイティブ描画矩形、オーバーレイ切抜き、端タップ、左右キー、動画の単タップ／ダブルタップとの競合、一覧保持、ブック移動を確認する。ユーザーの動画内容は再生・表示せず、Windows Shellからメタデータのみを確認する。

PC画面操作禁止の規則に従い、指定動画を実アプリで表示した目視確認とインストーラーGUIは未確認。コード署名証明書がないため、WindowsインストーラーはAuthenticode未署名。
