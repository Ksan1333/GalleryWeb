# PixVault for Windows アプリ仕様書 v0.7.3

更新日: 2026-09-14。対象: Windows 10/11 x64。以下以外はv0.7.2の仕様を継承する。過去版の成果物・仕様書は保持する。

## 動画のアスペクト比

- 動画ステージ全体は操作面として維持するが、WindowsのlibVLCネイティブ子ウィンドウは元動画のアスペクト比を保つ矩形へ合わせる。
- 動画の幅・高さが利用可能な場合、ステージ内へcontain相当で中央配置する。ステージが元動画より横長なら左右に、縦長なら上下に余白を残し、上下左右を切り取らない。
- 起動時はカタログのメタデータを使い、再生開始後にlibVLCが通知した実寸で更新する。実寸が未取得の場合のみステージ全体を暫定使用する。
- 透明canvasはネイティブ描画のアンカーであり、固有の300×150比率で表示領域を決めない。canvasはステージ全体へ絶対配置し、ネイティブ矩形の外側は動画ステージ背景を表示する。
- 操作バー、モーダル、一覧、レコメンド、ホバー案内等は、アスペクトフィット後のネイティブ矩形から切り抜く。元動画のファイル内容や解像度は変更しない。

## 前後移動とホバー案内

- メディア表示領域の左右端を450ms以内、移動14px以内でタップすると前後のメディアへ移動する。先頭・末尾では移動しない。
- 移動可能な端へマウスまたはペンを置くと、その端に薄い「前のメディア」または「次のメディア」と矢印を表示する。移動先がない端には案内を表示しない。案内は操作を奪わず、ネイティブ動画の描画からも除外する。
- 動画中央の単タップ再生／停止と左右ダブルタップシーク、画像のドラッグ・ズーム、ブックのページ操作は維持する。

## キーボード

- 画像、GIF、動画では、フォーカスが入力欄・ボタン等にないとき、左キーで前、右キーで次のメディアへ移動する。
- ブックでは通常の左右キーを綴じ方向に沿ったページ送りへ割り当てる。`Ctrl＋左キー`で前の本、`Ctrl＋右キー`で次の本へ移動する。PageUp／PageDown、Home／End、シークバー、画面上のページボタンも利用できる。

## 確認方法と未確認事項

合成データによるヘッドレスChromiumで、16:9動画を横長ステージへcontain配置した矩形、canvasとの寸法不一致、オーバーレイ切抜き、左右端ホバー案内、端タップ、左右キー、動画の再生・シークとの非干渉、ブックの左右キー／Ctrl＋左右キーを確認する。ユーザーの動画内容は表示せず、メタデータのみを扱う。

PC画面操作禁止の規則に従い、指定動画を実アプリで表示した目視確認とインストーラーGUIは未確認。コード署名証明書がないため、WindowsインストーラーはAuthenticode未署名。
