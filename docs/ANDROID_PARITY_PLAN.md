# Android 版との機能差分・移植計画

最終監査: 2026-08-23  
比較対象: Android `Gallery` 2.0.0 / Windows `GalleryWeb` 0.1.32

## 判断基準

- 画面だけでなく、実処理、永続化、失敗時の挙動、必要なテストが揃った時点で完了とする。
- Windows では物理フォルダー移動を提供せず、削除は Windows ごみ箱へ委譲する。この2点は Android と意図的に異なる。
- 自動更新は署名鍵と HTTPS 配信先が必要なため、アプリ内実装と配布基盤の準備を別の完了条件として扱う。

## Phase 1 の実装順

1. Androidが出力する9エントリーのZIPを固定上限付きで読み、形式・件数・SHA-256を検証する。
2. 相対パス＋容量、名前＋容量＋時刻、SHA-256の順で登録済みメディアと照合する。
3. 一致、曖昧、未検出、無効を確認画面へ表示し、曖昧な候補は自動採用しない。
4. 利用者の確定後、お気に入り、年齢区分、タグ、AI状態、ベクトル、しおり、資料、X履歴、設定を1トランザクションで保存する。
5. 同一アーカイブの再取り込みを安全にし、実行履歴と問題を `migration_runs` / `migration_issues` に残す。
6. Windows側の設定・お気に入りをJSONへ書き出し、検証後に復元できるようにする。

実装状況: 1〜6完了。曖昧な候補は自動採用せず、Phase 2で追加した手動解決UIから利用者が候補を個別指定できる。

## Phase 2 の実装状況

1. フォルダーグループをSQLiteへ保存し、作成、フォルダー追加／移動、改名、メンバー解除、グループ解除、並び替えに対応。
2. 日時順で隣接する画像・GIFだけをAIベクトルで比較し、設定した一致率以上の連鎖をグループ表示。全組み合わせ比較を避け、件数に対して線形時間で処理。
3. 詳細検索の全条件をSQLite設定へ保存し、保存件数1〜10件、条件復元、個別削除、全削除に対応。
4. Android移行の曖昧・未検出メディアを登録済みカタログから検索し、任意の項目だけ手動割り当てして原子的に確定可能。
5. Rust全テスト、Web本番ビルド、ブラウザー画面操作とコンソール確認を完了。

## Phase 3 の実装状況

1. 画像・GIFを90°ずつ一時回転し、メディア切替時に0°へ戻す表示処理を追加。元ファイルは変更しない。
2. 画像・動画・ブックごとに下部ツールバー先頭5項目を割り当て、ダブルクリックズームと動画送り秒数をSQLite設定へ保存可能。
3. 登録済みH.264 MP4を原本とは別の一時ファイルへ変換し、有効なGIFを検証後に確定。保存キャンセル、既存保存先、変換失敗をUIへ返す。
4. ブックのシーク開始位置を新しい順に1〜5件記憶し、ページバーのアンカーボタンから戻れるようにした。
5. 選択したローカル画像を管理キャッシュへ一時コピーし、完了・資料削除・プロジェクト削除時に管理パス内の一時資料だけを削除。
6. TypeScript型検査、Web本番ビルド、Rust releaseテスト105件（101成功・4件は外部依存のため無視）を完了。

## Phase 4 の実装状況

1. 登録フォルダーをOSのファイル変更イベントで監視し、変更内容が安定してから変更されたルートだけを再スキャン。未接続ドライブは全件消失として扱わない。
2. 監視で新しく追加された画像・GIFをSQLite設定内の待ち行列へ保存し、ほかのAIジョブと競合しない64件単位の標準分析を実行。失敗・キャンセル時は削除せず再試行する。
3. `pixvault-x://open?url=...` のユーザー単位Windows URLプロトコルと、X投稿URLのテキスト／URIドラッグ＆ドロップを追加。
4. Xメディアを投稿URL・メディアID・保存先の組み合わせで記録し、保存済みファイルが存在する場合だけ解析画面で「保存済み」として重複保存を省略する。
5. 視覚類似検索を旧Web独自の色・輝度124次元特徴から、MobileNetV3 Smallの1000次元意味特徴へ変更。L2正規化、コサイン類似度、全登録フォルダー、40%超、最大25件の検索条件をAndroidへ揃えた。
6. 旧ベクトルはモデルバージョン更新で自動的に再作成し、モデルは固定リビジョンとSHA-256を検証してローカルへ取得する。

## Phase 5 の実装状況

1. システム／ダーク／ライトのモード、Android版で表示対象となる20種類すべてのプリセット、背景・カード・文字・状態色・境界線のカスタム配色を追加。
2. 起動時の配色キャッシュ、Windowsの明暗設定変更への追従、ネイティブタイトルバーのテーマ同期を追加。
3. AI分析完了・停止・失敗とライブラリ監視による追加を、アプリ内履歴に加えてWindowsネイティブ通知へ連携。通知の無効化とテスト通知にも対応。
4. HTTPS更新先、更新署名公開鍵、Windowsコード署名証明書の有無をアプリ情報へ表示し、いずれかが欠ける配布版では自動更新を有効化しない境界を追加。
5. 秘密鍵をリポジトリやアプリへ含めない署名配布と、問題版から直前版へ戻すロールバック手順を文書化。

## 保留条件

- 自動更新の最終有効化には、Tauri更新署名の公開鍵、秘密鍵の安全な保管、`latest.json` と署名済みインストーラーのHTTPS配信先が必要。
- Windows 10/11クリーン環境、ネットワーク／リムーバブルドライブ、10,000件ライブラリーの最終試験は実機またはCI環境が必要。

## Phase 6 — 配布・安定性強化

1. ネイティブpanicとレンダラー異常を、利用者データを含めない2 MB上限のローテーションログへ記録。
2. SQLite `quick_check`、外部キー確認、安全な`PRAGMA optimize`とWALチェックポイントを設定画面から実行可能にする。
3. 正常なカタログだけを`VACUUM INTO`で別ファイルへ複製し、再度`quick_check`とSHA-256を確認する復旧スナップショットを追加。
4. Android版で表示対象となる20テーマの件数、ID、文字コントラストを自動試験する。
5. 10,000件カタログのページ取得、並び順、集計を回帰試験し、全組み合わせを読み込まない境界を維持する。
6. Windows CIで本番ビルド、性能予算、Rust Release試験、NSIS生成、バージョン・ハッシュ・署名状態を検証する。
7. Windows 10/11実機、署名証明書、更新署名鍵、HTTPS配信先は外部ゲートとして[リリースチェックリスト](RELEASE_CHECKLIST.md)で管理する。

## Phase 7 — ワークスペース型レイアウト

1. 既存機能を削らず、左ナビゲーション、ページコンテキスト、履歴移動、主要操作を一つのデスクトップシェルへ再編。
2. ホームをライブラリ状況、形式別ショートカット、お気に入り棚、保存場所の明確な情報階層へ変更。
3. 900px以下をドロワーナビゲーション、680px以下を1列カードへ切り替え、狭い画面でも全機能への導線を維持。
4. スキップリンク、ランドマーク、現在地、フォーカス表示を追加し、静的レイアウト規約で回帰を検出。
5. 変更前の0.1.25ソース4ファイルをSHA-256検証済みZIPへ保存し、プレビュー付き復元スクリプトを用意。

## Phase 8 — ギャラリー密度とビュワー

1. ギャラリーの隣接類似セクションと設定導線を外し、通常の検索・類似検索アルゴリズム自体は維持。
2. 画像ルートの仮想フォルダーグループを、星付きフォルダーへ直接移動できる小型一覧へ置換。
3. 画像・動画・ブックの日付グループを常に無効化し、更新順の連続表示へ統一。
4. 動画・ブックのルートフォルダーとメディアを小型化し、ファイル名と基本情報を保った高密度表示へ変更。
5. ビュワーの固定最大幅を廃止し、ウィンドウのほぼ全域へ比例して拡大。
6. 変更前の0.1.26対象7ファイルをSHA-256検証済みZIPへ保存し、限定復元スクリプトを追加。

## Phase 9 — 正方形ギャラリーとブック先読み

1. 画像フォルダーも動画・ブックと同じ小型ファイル行へ統一し、正方形サムネイルの右側へ基本情報を配置。
2. 通常グリッドを含む画像・GIF・動画・PDF・ZIP/CBZとフォルダープレビューの表示枠を正方形へ統一。
3. PDFを表示用JPEGへ変換し、ZIP/CBZとともにページ先読みを追加（Phase 10で操作優先の周辺キャッシュへ最適化）。
4. ページ番号ではなく表示スロット単位でcanvasを再利用し、ページ準備中の白いプレースホルダーと全画面ローディングを抑止。
5. 変更前の0.1.27対象6ファイルをSHA-256検証済みZIPへ保存し、限定復元スクリプトを追加。

## Phase 10 — 大規模ライブラリ性能

1. フォルダー監視を周期的な全件WalkDirからOSイベント方式へ変更し、入れ子ルートを含む変更をまとめて再スキャン。
2. 起動時のSQLite整合性検査を初回描画後へ移し、全サムネイル・全ベクトルの自動メンテナンスを明示／オンデマンド処理へ変更。
3. スキャン済み一時表と差分比較により、変更のないメディア行、最終確認時刻、更新時刻を書き換えないように変更。
4. ギャラリー更新をstale-while-revalidate化し、既存カードとスクロール位置を保ったまま読込済みページだけを再検証。
5. PDF Blobを48ページLRUへ制限し、現在ページ前後だけを操作停止後のアイドル時間に先読み。GIFはカードへポインターを重ねた場合だけ原本を再生。
6. 更新履歴・補助UIを遅延chunkへ分離し、初期JavaScript上限を320 KiB、gzip上限を100 KiBへ引き締め。
