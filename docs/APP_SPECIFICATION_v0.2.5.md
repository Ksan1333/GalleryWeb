# PixVault for Windows アプリ仕様書 v0.2.5

- 更新日: 2026-09-05
- 対象: Windows 10/11 x64、React/TypeScript + Tauri/Rust
- 配布: NSISセットアップEXE、アプリ版数0.2.5、DBスキーマ9
- 本版は抜本レビューの信頼性・操作統一フェーズと、外部起動/右綴じシークの改善を含む。過去版の仕様書と成果物は保持する。

## 1. 外部ファイル起動とExplorer

Windowsの「プログラムから開く」等で対応ファイルを渡すと、起動済み/未起動のどちらでも「全フォルダー」を選択し、対象ファイルの親フォルダーを表示する。その一覧に属するMediaViewerでファイルを開く。閉じると親フォルダーに留まり、最後に見ていたアイテム付近へスクロールを戻す。

親フォルダー直下のフォルダーとメディアを読み込むが、その操作だけで配下を再帰走査したり優先指定へ変更したりはしない。通常ギャラリーは引き続き優先フォルダー配下のみを表示する。

ファイルの位置は表示条件・並び順と同じ条件でSQLiteが求める。先頭から対象まで全件をフロントへ読み込まない。お気に入り/種類/検索等の条件が対象ファイルを除外する場合、または位置/件数照会が失敗した場合は、そのファイルだけを開く安全なフォールバックを使い、親フォルダーは維持する。

複数ファイルを一度に渡した場合、開始ファイルはcurrentId（通常は先頭）とし、その親フォルダーの一覧を閲覧対象にする。v0.2.4の「渡されたファイルだけを横断する一覧」からの変更である。同じ要求は1回だけ処理し、起動済みアプリへの次の要求では新しい親フォルダーへ切り替える。

通常パス、空白・日本語、ドライブ直下、UNC、Windowsの拡張長パスを扱う。絶対パスの実在する対応ファイルだけをネイティブ側で検証して受け付ける。既定アプリは強制変更しない。対応拡張子と安全なFIFO受け渡しはv0.2.4を継続する。

全フォルダーの戻る/進むは共通のマウス履歴操作に対応し、PC一覧も履歴に含む。履歴は最大100地点、同一アプリ実行中の画面切替で場所を維持する。モーダル中に「進む」で背後の画面へ遷移しない。ホームのお気に入りフォルダーは保存済みルートIDと相対パスから実際の場所を開く。

## 2. ブックの進行方向

既定の右綴じは、開始ページがシークバー右端、最終ページが左端。ドラッグ、目印、プレビュー、端のページ表示、左右キーを綴じ方向へ一致させる。左キーで先へ、右キーで前へ進む。左綴じでは逆方向とする。Home/Endは論理上の最初/最後であり、表示ページ番号は逆順にしない。

見開きの左右配置とページ送りは既存の右綴じ仕様を継続する。動画のシークバーと音量保存にはブック用の反転を適用しない。

## 3. 外部改名・移動と整理情報

DBスキーマ9にmedia_file_identitiesを追加する。WindowsではボリュームID・128bitファイルID・作成日時を保存し、次の走査で同じ実体を確認できる場合にメディアIDを再利用する。お気に入り、タグ、しおり等のIDに結びつく情報を保持する。

内容を全読み込みしてハッシュを計算する方式ではなく、共有可能なメタデータハンドルで取得する。コピー/ハードリンク/複数候補/切断された元ルートを安易に結合しない。同じパスの別ファイルへの置換では識別情報を更新する。移動済みIDを古いルートの削除イベントで再び欠損化しない。

制限: この版で識別情報を記録する前の改名、対応しないファイルシステム、別ボリュームへの移動は自動照合できない。既に取り残された古いレコードを名前やサイズだけで推測して結合しない。既存ファイルへ適用するには、この版で対象フォルダーを読み込み/再スキャンする。

DBは8から9へ追加移行する。旧EXEへ戻すだけでDBを元に戻せるとは保証しない。必要な場合は更新前カタログのバックアップを保持する。

## 4. ブックの派生キャッシュ

原本は変更せず、アプリデータのbook-pages/book-coversに派生画像を保存する。

| 種別 | 容量上限 | ファイル上限 | 直近の保護 |
| --- | ---: | ---: | ---: |
| ZIP/CBZ展開ページ | 2 GiB | 20,000 | 32ページ |
| 表紙 | 256 MiB | 4,000 | 8枚 |

更新日時・サイズによる世代分け、最終利用順の回収、30日未使用の回収を行う。生成と回収を直列化し、原本ではなく管理ルート内の派生ファイルだけを対象にする。回収は要求時に行い、通常の定期確認は5分間隔以上とする。全ブックを開くたびに全ページを展開しない。既存の周辺17ページの先読みと表示中の画像/キャンバスを維持する。

抽出処理の途中は一時的に上限を超える場合がある。保護されていない古いデータを回収できない場合は、無制限に書き続けずエラーにする。回収済みURLを長期再利用しないよう、ページ再訪時はネイティブで存在を確認し、必要なら再展開する。アーカイブ更新時の表紙も新世代へ切り替える。

本版には使用量表示・手動一括削除ボタンは含めない。元ファイルを削除した瞬間の専用キャッシュ削除ではなく、世代/期限/容量に基づく回収で管理する。

## 5. 一覧とビュワーの操作

ギャラリー・全フォルダー・お気に入り・媒体別フォルダーで、現在の検索や種類等の条件を保って全件をページ取得する。通常一覧の64件×8ページ保持、仮想化、サムネイル同時処理制限は維持する。

コンパクト表示の目標カード幅は最小88/小100/標準112/大148/最大200px。実際の幅はウィンドウから列数を算出して調整する。サムネイルと文字を含むカード全体を正方形にする。名前11px、補足10pxを基本とし、全フォルダーの長い名前は既存の2行表示を維持する。

選択中もEnterまたは明示的な「開く」操作で、選択を保ったまま閲覧できる。ホームから開いた場合も、ごみ箱移動後に次のメディアがあれば表示を続ける。最後の1件では閉じる。

ビュワーを開くとフォーカスを移し、Tabを内部で循環させ、背景操作をinertで停止する。子ダイアログとメニューを優先し、Escape/矢印が背後のビュワーへ重複伝播しないようにする。

## 6. 設定と診断

現行の設定画面に、標準テーマ/20プリセット/8色カスタム、ファイル変更監視、新規画像の自動AI分析、Windows通知と通知テストを復旧する。設定保存の成功後に適用し、失敗時は保存済みの状態を維持する。

診断には整合性確認、レポート出力、メンテナンス、復旧用コピーを設ける。変更系操作は正常な診断結果を確認後に利用可能とし、問題検出時・診断等の失敗時は再確認を求める。レポートにメディア名/パス/タグ/設定値は含めず、復旧用コピーは原DBを上書きしない。

バックアップ復元後は配色と通知へ新しい設定を反映する。復元後の再取得失敗は「復元自体の失敗」と区別する。設定キャッシュは世代管理し、復元/保存前の遅い応答が以前の設定を再適用しない。

アクセントの文字色は実際のコントラストを計算して決める。標準プリセットはプロジェクトの目標4.5を満たす出力色を検査する。カスタムの本文/背景の組み合わせすべてに可読性を保証するものではない。HTMLの言語は日本語、faviconは製品アイコンとする。

## 8. 検証・リリース

PDF表示はPDF.js 6.2.108以降の互換6.xを使用する。GHSA-hq66-cqwq-w95jの修正版へ更新し、PostCSS/nanoidのビルド依存警告も解消する。PDF.js公式アドバイザリーの成立条件はスクリプト機能の有効化等であり、このアプリのcanvas描画だけで攻撃が成立したと確認したものではない。今回の更新は既知の影響版を配布物へ残さないための予防措置である。

型検査、本番Webビルド、Node単体/実装連携、Rustリリーステスト、生成NSISの関連付け、SHA-256を確認する。ヘッドレスでは全フォルダー6サイズ、22万件相当の隔離ライブラリ、外部ファイルの深い位置・再起動要求・閉じた後の場所とスクロールを検査する。外部Explorer統合テストのビュワー表示部分はテスト用に置換し、実ビュワーの方向/フォーカスは別の実装テストで確認する。

追加のPDF検証ではメモリ内で合成した3ページのPDFを実PDF.js workerと実BookViewer/PdfThumbnailで読み、表紙生成、各ページの色、左右綴じのシークキー、右綴じの見開き順、閉じた後の派生画像Blob URL解放を確認する。テスト対象は専用のヘッドレスページのみで、アプリやOSの画面取得は行わない。

画面操作・スクリーンショット・ユーザーの実メディアへの変更は行わない。実機の見た目、OSの関連付け選択画面を手操作した確認、公開ネットワークや外部モデルが必要な明示的除外テストは未確認とする。署名証明書が未設定の場合、インストーラーは未署名である。

配布先: release/0.2.5/PixVault for Windows_0.2.5_x64-setup.exe。版数定義を一致させ、CHANGELOG・本仕様書・ソースと検査をコミット/プッシュし、0.2.5タグのReleaseにEXEとSHA-256を添付する。

配布物・実行ファイル・DLL・シンボルをrelease/0.2.5へ退避して一致を確認後、使用中のプロセスがないことを確認しcargo clean --manifest-path src-tauri/Cargo.tomlを実行する。再生成可能なVite検証キャッシュも対象を確認して削除し、node_modules本体、原メディア、SQLite、ユーザーキャッシュ、dist、過去版の成果物は保持する。実行結果と削除容量はリリース確認記録に記載する。
