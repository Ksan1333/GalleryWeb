# PixVault for Windows アプリ仕様書 v0.3.0

更新日: 2026-09-10。Windows 10/11 x64、DBスキーマ9（変更なし）。以下以外はv0.2.11の仕様を継承する。v0.2.11の互換動画変換・FFmpeg取得・変換キャッシュ管理は廃止する。

## 動画再生

Windowsインストール版ではlibVLC 3.0.23がカタログ上の元動画を直接読み込む。元ファイルを変更せず、再圧縮した動画や一時動画は作らない。ブラウザプレビューはHTML video再生を継続するが、互換変換へのフォールバックはない。

同梱DLLを明示的な絶対パスと安全なDLL探索フラグで読み込む。システムのVLCインストールやPATH、ユーザーのVLC設定には依存しない。Windowsの内部形式のパスはlibVLC向けに通常の絶対パス／UNCパスへ正規化する。再生エンジンはビルド時に公式アーカイブを取得し、固定SHA-256で検証。アプリ起動時・再生時にはエンジンをダウンロードしない。上流ライセンスとソースの案内を同梱する。

再生・停止・シーク・音量・ミュート・ループは専用ワーカーへ送る。libVLCの映像コールバックで得るBGRxフレームを、32バイト整列バッファと再利用プールで保持する。表示時刻に届いた最新フレームだけをバイナリIPCで渡し、WebGLで描画する。JSON/base64、JPEGエンコード、全動画データの保持は使わない。同時フレーム取得は1件で、画面が隠れている間は取得を抑止する。

読み込みとエラーは画面端に小さく表示し、次へ・閉じる・他の操作をロックしない。失敗時の再試行は元動画を開き直すだけで、変換はしない。30秒映像が届かなければエラー案内を出す。

## 既存の操作とライフサイクル

ダブルタップ前後移動、マウス・キーボード操作、通常／相対シーク、音量ホイール、ミュート、ループ、全画面、表示中フレームのPNG/JPEG保存を維持する。シーク中は表示中フレームの縮小プレビューを使い、別の動画デコーダーを増やさない。

大音量分析は短時間の音声専用libVLCプレイヤーを使用する。RMS 0.22以上、またはpeak 0.98以上かつRMS 0.12以上で大音量と判定。初期出力と大音量時の出力は50%を上限とし、低い保存音量を勝手に上げない。ユーザーが音量を変更した後は解析結果で上書きしない。音声解析のサンプルはメモリーのみ、最大8秒相当・解析待機約5秒まで。

切り替え・終了・エラー時は旧セッションを停止する。遅いopen結果も閉じ、描画フレームを蓄積しない。ごみ箱移動では元ファイルのハンドル解放完了を最大10秒待ってから移動し、失敗した場合は再生を開き直す。元動画を消す操作は従来の明示的なごみ箱操作だけ。

表示前のフレームも所有マップで管理し、表示前に停止した場合にピクセルバッファが残らないよう解放する。保存済み音量の非同期復元はユーザー操作と区別し、大音量保護を解除しない。ループ・ミュートの設定同期は音量同期から分離し、保存音量を巻き戻さない。

## 配布と制約

- libVLC同梱によりインストーラー容量は増加する。DLLとプラグイン、上流のライセンス・著作者情報を保持し、対応VLCソースアーカイブをReleaseにも添付する。
- 表示用ピクセルは最大1920×1080・SDR。元動画の解像度・ファイルは維持するが、4K原寸・HDRの忠実な表示は本版の対象外。GPU直接描画ではないため、高解像度／高フレームレートでは負荷が増える場合がある。
- DRM・破損・未対応形式等はlibVLCでも失敗する場合がある。特異な画素比・HDR・外部字幕等は検証対象外。
- 旧FFmpeg・互換動画キャッシュは使用しないが、既存アプリデータを自動削除する移行処理は入れない。
- GIFへの明示的な書き出し機能は、廃止した「再生のための動画変換」と別機能として維持する。
- 実機WebView2画面とインストーラーGUIは操作禁止のため未確認。実機の滑らかさ・AV同期・音の出方については合格を保証しない検証版として配布する。
- Linux／ブラウザでは従来のHTML video経路を残し、Windows DLLを読み込まない。Linux版のビルドは今回の検証対象外。

## 検証と配布手順

ヘッドレスの操作／GPU描画テスト: `node scripts/test-vlc-playback.mjs`、`node scripts/test-viewer-interactions.mjs`。

ネイティブの合成動画検証: `node scripts/prepare-libvlc.mjs --source`、テスト専用`PIXVAULT_TEST_FFMPEG`を設定して`node scripts/create-vlc-fixtures.mjs`を実行。`PIXVAULT_VLC_FIXTURES`を`src-tauri/target/vlc-fixtures`の絶対パスに設定し、`cargo test --manifest-path src-tauri/Cargo.toml --release vlc_playback -- --include-ignored`で実デコーダーを検証する。FFmpegは合成入力を作るテスト専用で、アプリには同梱も実行もされない。

`npm run build:installer`後に`scripts/check-release-artifacts.ps1`で版数・メタデータ・SHA-256を確認する。`node scripts/preserve-windows-release.mjs`は`release/0.3.0`へEXE・シンボル・ランタイム・ライセンス・VLCソースを退避し、全コピーのSHA-256一致を検証する。既存の版数ディレクトリーは上書きしない。退避後に`cargo clean --manifest-path src-tauri/Cargo.toml`で再生成可能なビルドキャッシュを削除する。
