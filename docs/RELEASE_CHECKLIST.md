# Windowsリリースチェックリスト

## 自動ゲート

`.github/workflows/windows-release-gate.yml`はWindowsランナーで次を順番に確認する。いずれかが失敗した成果物は配布しない。

- npmロックファイルからの再現インストール
- TypeScript型検査とVite本番ビルド
- 起動バンドルの性能予算
- 起動遅延、イベント監視、ギャラリー更新、GIF、ブックLRUの性能契約
- Releaseサムネイルベンチマークのwarm p95、cold上限、並列スループット
- Android版で表示対象となる20テーマの件数、ID重複、本文・補助文字・ボタン文字のコントラスト
- RustフォーマットとRelease全テスト
- 10,000件カタログの中央ページ取得、集計、並び順
- NSISインストーラーの生成
- package、npm lock、Cargo、Tauri、EXEのバージョン一致
- EXEの最小容量、SHA-256、Authenticode状態を記録した`release-manifest.json`

署名済み一般配布では、`scripts/check-release-artifacts.ps1 -RequireSignature`を使い、Authenticodeが`Valid`以外なら失敗させる。

## 診断と復旧

1. 設定の「整合性を確認」を実行する。
2. `要確認`の場合は自動メンテナンスやスナップショットを実行せず、診断レポートを新規ファイルへ保存する。
3. `正常`の場合だけ復旧スナップショットを作成する。元カタログは変更されず、別のSQLiteファイルを`quick_check`とSHA-256で検証する。
4. 復旧が必要な場合はアプリを終了し、元DBと復旧スナップショットの双方を保全してから作業する。使用中のDBへ画面から上書き復元する機能は提供しない。
5. 診断レポートにはメディアパス、ファイル名、タグ、設定値を含めない。クラッシュログは2 MBでローテーションする。

## 外部ゲート

- 信頼されたWindowsコード署名証明書
- 保護された更新署名秘密鍵とアプリへ固定する公開鍵
- `latest.json`と署名成果物を置くHTTPS配信先
- 署名済み更新の正常、改ざん、中断、ロールバック試験

これらが揃うまでは自動更新を無効のままにし、未署名のローカル検証用EXEを一般配布しない。
