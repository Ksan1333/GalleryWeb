# PixVault for Windows アプリ仕様書 v0.3.1

更新日: 2026-09-10。Windows 10/11 x64、DBスキーマ9（変更なし）。以下以外はv0.3.0の仕様を継承する。過去版の仕様書・成果物は保存する。

## libVLC初期化の修正

Tauriは実行ファイルをcanonicalizeしてリソースディレクトリーを返す。Windowsではこのパスが`\\?\C:\...`形式となる。v0.3.0はその形式のままDLLを読み込んでいた。DLL自体の読み込みには成功するが、libVLC 3.0.23のプラグイン探索が失敗し、`--avcodec-threads=2`を認識できず初期化に失敗することを、インストール済みDLLの独立CLI呼び出しで再現した。

v0.3.1は`libvlccore.dll`と`libvlc.dll`のいずれを読み込む前にもパスを正規化する。ドライブの内部プレフィックスを除き、`\\?\UNC\server\share`は`\\server\share`へ変換する。空白・日本語を保持し、NUL文字とUnicodeに変換できないパスは拒否する。DLL探索の安全なフラグは維持し、カレントディレクトリー変更・環境変数変更・システムのVLCへの依存は追加しない。

元動画のパスにも共通の正規化処理を使う。互換変換やFFmpeg取得は復活させない。元動画・ライブラリDB・既存ユーザーデータは変更しない。

## 回帰検証

`cargo run --manifest-path src-tauri/Cargo.toml --release --example vlc_initialization_probe -- <vlcディレクトリー>`は独立したCLIプロセスで、本番と同じローダー・引数を用いてcanonicalパスから初期化する。ウィンドウ・メディアプレイヤーを作らず、音声を出さず、カタログへアクセスしない。この検証をWindows CIに追加する。

既存の実デコーダーテストもDLLディレクトリーをcanonicalizeしてから渡す。これにより、通常パスだけを検証して実アプリのパス条件を見落としたv0.3.0の検証不足を補う。

## 配布・制約

配布先は`release/0.3.1/PixVault for Windows_0.3.1_x64-setup.exe`。旧アプリを終了してから更新し、再起動する。失敗結果はプロセス内で保持されるため、実行中の旧版は自動的には直らない。実行中アプリの強制終了・自動更新は行わない。

最大1920×1080・SDR表示、DRMや破損等は未対応の場合があるという制約は継続。実機WebView2・音声出力／AV同期・インストーラーGUIは操作禁止ルールに従い未確認とする。配布物は署名なしの検証版。

## 確認結果

- インストール済みDLLを通常パスで読み込むと成功、内部形式のパスでは初期化に失敗することを、別プロセスのCLIで再現。
- 修正後の本番ローダーは、インストール済みのディレクトリー・日本語と空白を含むコピー先・ビルド用ディレクトリーの3条件すべてで、canonicalパスからの初期化に成功。
- TypeScript検査・Vite本番ビルド・パフォーマンス上限・Rust整形検査・libVLCバイナリ転送／描画のヘッドレス試験が成功。
- ビュワー操作試験は、並行ビルド中に低速ダブルタップ1件が失敗した。入力コードを変更せず、ビルド終了後に単独再実行して全項目成功。タイミング依存の可能性が残るため、初回の失敗も記録する。
- Rust通常テスト180件＋Windowsパス統合1件成功。libVLC専用8件は条件付きテストも含めて成功し、合成5形式の映像／音声復号・音量・シーク・ファイル解放を確認。外部AI/Xに依存する4件は未実行。
- NSISインストーラー生成・版数／署名状態検査・生成NSISを含むファイル関連付け11件が成功。EXE、シンボル、同梱ランタイム、対応ソース等599ファイルを`release/0.3.1`へ退避し、コピー元とのSHA-256一致を確認。
