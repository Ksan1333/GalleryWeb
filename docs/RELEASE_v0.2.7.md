# PixVault for Windows 0.2.7 — ライト情報表示と動画入力の検証版

2026-09-06 / Windows x64 / DBスキーマ9

## 変更内容

- レコメンド欄の本文・ラベル・パス・ボタンをテーマに追従させ、ファイル情報を10〜11pxへ拡大。
- ライトモードのビュワー周辺UIを明るい配色へ変更。メディア表示面は暗いまま保持。
- 動画の左右ダブルタップをPointer Eventsで判定。dblclickを生成しない環境でも動作し、単発操作との競合を防ぐ。
- ダブルタップも設定済みのシーク秒数を使用。ドラッグ/キャンセル/終了後の残留操作を防ぎ、キーボードで動画面を操作可能にする。

変更履歴: `CHANGELOG.md` / 仕様書: `docs/APP_SPECIFICATION_v0.2.7.md`。

## 名前順の調査結果（未修正）

通常の動画一覧と索引付きサムネイル列は同じ名前順だった。一方、ブックの「前の本/次の本」はキャッシュのMap挿入順を使い、一覧の索引順と一致しない場合がある。合成データの1.zip/10.zip/2.zipを索引2,0,1の到着順にすると、レールは正しい1,10,2のまま、10.zipから次の本へ進めない問題を再現した。画像スライドショーも同じ配列由来の構造である。

この項目は調査依頼の範囲で原因を記録したもので、修正済みではない。名前のSQLソート自体は自然数順ではなくNOCASE文字列順。利用者の実データでの発生状況までは確認していない。

## 確認内容

- TypeScript、Vite本番ビルド、起動/容量/レイアウト/テーマ契約は成功。
- 実コンポーネントの情報欄を20プリセットで測定し、検査要素のコントラスト4.5:1以上。既定ライトのファイルラベルは約8.05:1、値は約16.85:1。8pxラベルを10px、値/パスを11pxへ変更。
- 動画フォルダー画面から開く実ビュワーで、マウス、dblclickを抑止したタッチ、350ms間隔のダブルクリック、単発、ドラッグ、キャンセル、Enter、閉じた後のタイマー破棄を確認。
- Node回帰は失敗0。初回は生成済みNSIS未作成のため該当検査1件を除外し、インストーラー生成後に必須条件で再実行する。
- 全フォルダー6サイズ、22万件相当の一覧（初期48カード・30回小スクロールで追加カード再描画/ページ照会0）、外部ファイル先行表示、深い位置、実PDF workerとRTL/LTR/見開き/Blob解放の回帰検証は成功。
- Rust本体は版数以外変更なし。リリーステスト、サムネイルベンチマーク、NSIS生成と関連付け、版数/署名状態/ハッシュ検査、GitHub Windows CIの最終結果は、配布EXEと照合して公開するRelease本文へ記録する。未実行の結果を成功とは扱わない。

起動JS約319.5 KiB/gzip99.5 KiB、CSS約114.7 KiB/gzip22.1 KiB。起動/個別chunkの上限を維持し、遅延ビュワーと履歴の追加分として総上限だけ2614→2620 KiB（測定約2616.7 KiB）とした。
