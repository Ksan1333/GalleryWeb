# PixVault for Windows アプリ仕様書 v0.8.0

作成日: 2026-10-14。アプリ全体の既存仕様はv0.7.10およびその参照仕様を継承し、以下を変更する。

## 動画エンジン

- Windowsでは対応可能なMIMEをWebViewで再生する。非対応MIMEはMedia Foundationで直接開く。
- WebViewのデコードエラー、8秒以内に再生開始または有効な総時間を取得できない場合、5秒以内にシークが完了しない場合はMedia Foundationへ切り替える。
- Media FoundationはIMFMediaEngineを専用COMスレッドで使用する。既存の子ウィンドウへ描画し、Reactの動画操作UIから共有IPCで制御する。フレームサーバー/DOM Canvas転送は使用しない。
- Media Foundationでエラーや読み込み8秒・シーク5秒のタイムアウトが起きた場合はVLCへ進む。VLC失敗はエラー表示し、再試行可能。
- 操作欄からWebView→Media Foundation→VLCへの手動切り替えも可能。現在位置・一時停止を引き継ぐ。音量・ミュート・ループは設定値を適用する。
- 元動画の変換・置換・一時動画作成はしない。非Windows環境はWebViewを維持する。
- セッション終了はCOM Media EngineのShutdown、ファイル解放、表示ウィンドウ終了を待つ。既存の削除前セッション終了処理を共有する。

## シーク

- メタデータ通知を受信する前に登録された総時間を保持し、通知が購読より早い場合も現在のメタデータを初期同期する。
- 総時間が不明ならシーク範囲は無効化し、つまみを先頭に置く。
- Media Foundationは非同期SetCurrentTimeで移動し、処理中の要求は最新位置にまとめる。

## 制約と検証範囲

- OSのコーデック構成に依存。Media Foundationへ替えることで全形式対応や高速化を保証するものではない。
- Media Foundation経路ではフレーム画像保存、シーク画像プレビュー、自動音量補正は未対応。VLCへ切り替えて利用する。
- 子ウィンドウ方式を維持するため、描画重なりの全面的な解消は保証しない。
- ヘッドレステストでエンジン選択と失敗時遷移を検証する。Rustテストで無音の合成WAVを使い、実Media Engineの読み込み・シーク・解放を検証する。
- 実WebView2の映像、DPI、音声同期、ユーザーの問題動画でのシーク・起動時間は未確認。

## 配布

- Windows NSISインストーラー。VC++ランタイム同梱とlibVLC同梱はv0.7.10の仕様を維持する。
- 旧版成果物・タグ・仕様書は保存する。
