## 1. Windowsから直接開く

NSISインストーラーは、PixVaultを対応メディアのViewerおよびWindowsの「プログラムから開く」候補として登録する。既定のアプリを強制変更せず、利用者がWindows上でPixVaultを選択する。選択した形式は、以後エクスプローラーのダブルクリックからPixVaultへ渡せる。

| 分類 | 拡張子 |
| --- | --- |
| 画像 | jpg、jpeg、png、webp、bmp、heic、heif、avif、tif、tiff |
| GIF | gif |
| 動画 | mp4、m4v、mov、mkv、webm、avi、wmv、mpeg、mpg、ts、m2ts |
| ブック | zip、cbz、pdf |

登録対象はRustカタログの対応形式と一致させる。`OpenWithProgids`、`RegisteredApplications`、Capabilities/FileAssociationsをユーザー単位で登録し、変更後はExplorerへ関連付け更新を通知する。アンインストール時はPixVaultの候補登録を削除し、インストール前の関連付けが保存されている場合は復元する。上書き更新時にPixVault自身を旧関連付けとして上書きしないよう、PixVault以外の既存ProgIDだけを別キーへ保存する。実行ファイルとファイルパスの両方を引用符で囲み、空白を含むパスも1ファイルとして扱う。

関連付けはファイルをPixVaultのビュワーへ渡せることを示す。HEIC/HEIFと、AVI・WMV・MPEG・TS等を含む動画コンテナーや内部コーデックの実デコード可否は、Windows/WebView2に利用可能なデコーダーへ依存する。デコーダーがない場合もカタログ登録とビュワー起動は行うが、内容の表示・再生エラーを通知する。

## 2. 起動と受け渡し

未起動時はプロセス起動引数から対応ファイルを取得する。起動済みの場合はsingle-instance機構で新しいプロセスを終了し、既存のPixVaultへ引数を渡してメインウィンドウを前面へ戻す。Xダウンロード用の`pixvault-x`入力も、単一インスタンス化後の既存ウィンドウで引き続き受け取る。

外部メディアはネイティブ側のFIFOキューを正とする。フロントエンドイベントはキュー取得の通知にだけ使い、イベントpayloadをファイル情報として信用しない。通知と初期表示が競合しても取りこぼさないよう、購読開始後に起動時キューを取得する。取得処理は同時実行せず、処理中の追加通知は終了後にもう一度取得する。キューはcanonical pathで重複を除き、最大128件に制限する。

複数ファイルが同時に渡された場合は引数順を保って1つのビュワー一覧へ表示し、先頭を現在項目とする。新しい外部要求が届いた場合は、その要求の一覧へ切り替える。通常のMediaViewerを共用するため、画像・GIF・動画・ブックの表示、お気に入り、タグ、年齢区分、全画面、ごみ箱移動後の次項目表示を維持する。

## 3. 差分読み込みと表示範囲

外部ファイルを開く処理では親フォルダーを再帰走査しない。既存カタログルートのうち対象を覆う最も狭いルートを再利用し、該当しない場合だけ親フォルダーを非優先ルートとして登録する。その後、指定されたファイルパス1件だけを差分照合してMediaItemへ変換する。

この操作で優先フォルダーの設定を勝手に変更しない。優先フォルダー外のファイルは「全フォルダー」や種類別フォルダー、お気に入りから利用できるが、0.2.3で導入した優先フォルダー限定の通常ギャラリーへは追加しない。既にカタログにあるファイルは既存IDを再利用し、タグ・お気に入り等を保持する。元ファイルの移動・複製は行わない。

## 4. 入力の安全性と障害時動作

外部入力として受け入れるのは、現在存在する絶対パスの通常ファイルかつ対応拡張子だけとする。相対パス、HTTP/file URL、コマンドラインフラグ、フォルダー、不在ファイル、制御文字を含む値、Unicodeとして安全に扱えないパスは無視する。受け取り時とカタログ反映直前の両方でファイルと形式を再確認する。

ネイティブキューのロック異常はpanicさせずエラーとして返す。複数入力の一部だけに問題がある場合は開ける項目を表示し、失敗内容を診断ログへ残す。全件失敗時はフロントエンドへエラーを返して通知する。外部入力を直接HTMLやシェルコマンドとして実行しない。

## 5. 継続する仕様

優先フォルダー限定ギャラリー、全フォルダー、ファイル監視、64件ページング、仮想スクロール、正方形コンパクトタイル、サムネイル遅延読み込み、全画面、右綴じブック、動画音量保存、削除後の次メディア表示、AI分析、Xダウンロード、Android移行を維持する。

ブックページ、サムネイル、動画プレビュー等の既存キャッシュ仕様は変更しない。外部ファイルを開くために別の元ファイルコピーは作成しない。ビルドクリーンでは元メディア、SQLite、ユーザーキャッシュ、`node_modules`、`dist`、過去版の配布物を削除しない。
