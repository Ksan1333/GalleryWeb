# 署名付き更新の運用

PixVault for Windowsは、署名やHTTPS配信が未構成の更新を受け入れない。0.1.24では配布要件の診断を実装し、すべてが揃うまで自動更新を無効にしている。

## 必須の外部構成

| ビルド時の値 | 用途 | 保管方針 |
| --- | --- | --- |
| `PIXVAULT_UPDATE_ENDPOINT` | `latest.json`を置くHTTPS URL | 公開情報。HTTPS以外は未構成扱い |
| `PIXVAULT_UPDATE_PUBLIC_KEY` | 更新ファイルの署名検証 | 公開鍵だけをアプリへ埋め込む |
| `PIXVAULT_WINDOWS_CERTIFICATE_THUMBPRINT` | Windowsコード署名証明書の識別 | 証明書と秘密鍵はCIの保護ストアで管理 |

更新署名の秘密鍵とコード署名秘密鍵は、ソース、環境設定例、ログ、アプリ本体、更新サーバーへ保存しない。アプリ情報画面には値そのものを返さず、構成済みかどうかだけを表示する。

## 有効化ゲート

1. Windows 10 22H2とWindows 11のクリーン環境で、署名済みインストーラーの新規導入と上書き更新を確認する。
2. 更新メタデータと更新ファイルを同じ管理下のHTTPS配信先へ置く。
3. アプリ内の固定公開鍵で、正常な署名、改ざんファイル、別鍵の署名、期限切れメタデータを試験する。
4. ダウンロード中断、ディスク不足、アプリ再起動、更新拒否で現行版とSQLiteが破損しないことを確認する。
5. すべてを通過したビルドだけで署名検証付き更新処理を有効化する。

HTTPへの降格、署名検証のスキップ、公開鍵のネットワーク取得、署名失敗時の手動続行は提供しない。

## ロールバック

1. 問題のある`latest.json`を配信対象から外し、新規更新を停止する。
2. 直前の正常版を、現在版より高い修正版番号で再ビルドする。Tauri設定ではダウングレードを許可しないため、古い番号を再配信しない。
3. 修正版のインストーラーと更新成果物を同じ鍵で署名し、クリーン環境と既存データを保持した上書き更新を確認する。
4. 修正版の`latest.json`を公開し、更新率と起動失敗を監視する。
5. SQLiteスキーマ変更を伴う版では、前方互換の修正マイグレーションを提供し、データベースファイルを古い形式へ直接戻さない。
