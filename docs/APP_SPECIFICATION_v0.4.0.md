# PixVault for Windows アプリ仕様書 v0.4.0

更新日: 2026-09-10。対象Windows 10/11 x64、DBスキーマ9。以下以外はv0.3.1の仕様を継承する。過去版は残す。

## 動画再生の構成

同梱libVLC 3.0.23で元ファイルを直接開き、`libvlc_media_player_set_hwnd`でアプリ内の専用子ウィンドウへ描画する。Direct3D11出力を優先し、GPUデコードを自動選択、未対応コーデックはソフトウェアデコードへフォールバックする。CPUデコーダーの固定2スレッド制限を廃止して自動選択する。

通常再生では`libvlc_video_set_callbacks`を呼ばない。このAPIはlibVLC 3.0.23内部で`avcodec-hw=none`を設定するため。従来のCPU側RV32画像・フレームごとのバイナリIPC・WebGL描画ループは本番経路から除去。旧方式は比較検証用の`cfg(test)`内にだけ残す。

フルHDへの強制縮小はネイティブ出力に適用しない。ソース解像度を表示領域に合わせてネイティブ側で調整する。GPU／ドライバー／形式に依存するため、全動画・HDR色再現・DRM再生を保証しない。Linux／通常ブラウザーは既存のHTML動画再生を継続。

## UIとの統合

- 映像ウィンドウと低不透明度の入力専用ウィンドウはメインウィンドウの子として作成する。独立した最前面ウィンドウや外部VLCアプリは起動しない。
- 別スレッドの子ウィンドウ作成は親へのWindowsメッセージを伴うため、起動コマンドを非同期化し、作成待ちはブロッキングワーカーで行う。WebViewのUIスレッドを待機させない。
- フロントエンドは表示領域と操作UIの矩形のみ送る。変更時の送信に加え約1秒間隔の生存通知を行い、動画フレームに連動したIPCは行わない。
- 操作パネル、情報パネル、通知、全画面終了ボタン等と重なる箇所を映像と入力の両領域から切り抜く。モーダル表示中は映像領域を非表示にする。同期式の削除確認を出す前にも明示的に退避する。
- 座標はCSSピクセルと物理ピクセルをDPI倍率で変換する。Windows互換性とPerMonitorV2を宣言した同じマニフェストを本番・テストへ組み込む。
- クリック・左右ダブルタップ・ホイール入力は既存React操作へ渡す。通常の矢印カーソルを使用し、`ShowCursor`・`SetSystemCursor`によるグローバル変更はしない。操作中の入力捕捉はボタン解放・捕捉喪失・非表示・終了時に解除する。
- 画面遷移時は古い表示領域を隠し、libVLCの停止とファイル解放を待ってから子ウィンドウを破棄する。停止完了後にごみ箱へ移す。生存通知が3秒途切れた入力領域は自動的に非表示にする。

## キャプチャ・一時ファイル

通常再生時には画像や互換動画ファイルを作らない。キャプチャ要求または220ms落ち着いたシークプレビュー要求に限って、libVLCのPNGスナップショットを取得する。プレビューは幅320、保存用は最大幅3840。専用のUUID付き一時フォルダーで取得し、読み出し成功・エラー・タイムアウトのいずれでもファイルとフォルダーを解放する。ユーザーが明示的に保存した画像は削除しない。元動画とDBは変更しない。

## 検証方法

- `node scripts/test-vlc-playback.mjs`: 実際のフロントエンド実装をヘッドレスChromiumで検証。DPI、矩形切り抜き、モーダル退避、入力、シーク／音量、明示キャプチャ、終了と遅延起動、フレームIPCがないこと。
- `node scripts/test-viewer-interactions.mjs`: 実際のReactビュワーへネイティブ入力イベントを渡したダブルタップ、既存のマウス／タッチ／キーボード操作、20テーマの情報文字のコントラスト。
- `cargo test --manifest-path src-tauri/Cargo.toml --release`: 通常Rustテストと非表示の実HWNDライフサイクル／領域切り抜き検証。
- テスト専用FFmpegを`PIXVAULT_TEST_FFMPEG`へ指定し、`node scripts/create-vlc-fixtures.mjs --performance`で合成5形式と1080p60動画を生成。FFmpegはアプリ依存でも配布物でもない。
- `PIXVAULT_VLC_FIXTURES`へ`src-tauri/target/vlc-fixtures`の絶対パスを指定し、`cargo test --manifest-path src-tauri/Cargo.toml --release --lib vlc_ -- --include-ignored --test-threads=1 --nocapture`で実デコーダーを検証。親ウィンドウは非表示、音声は出さず、ユーザー動画を使わない。
- 性能比較は同じ合成H.264 1080p60を7秒ずつ再生し、プロセスCPU時間・libVLC表示フレーム数・欠落数・CPU画像コピー量を記録する。旧方式側にはWebView2への転送や描画負荷は含まない。実画面の滑らかさやAV同期の測定ではない。

## 未確認項目

実機WebView2との見た目の重なり、実画面での滑らかさ、音声出力とAV同期、HDR、多画面DPI切り替え、インストーラーGUIは未確認。PC画面やカーソルを操作せず、非表示の検証用ウィンドウとヘッドレス試験で確認する。署名なしの検証版として公開する。

## 確認結果

- Ryzen 5 3600／GeForce RTX 3060で検証。非表示のネイティブ子ウィンドウ作成・領域の切り抜き・破棄を確認。実際の動画プレイヤーはDirect3D11とD3D11VAモジュールを読み込んだ。
- Rust通常182件とWindowsパス統合1件が成功。libVLC／ネイティブ表示の専用12件は条件付き試験も含めて成功。合成5形式の動画とPNG取得、音量・シーク・ファイル解放を確認。外部AI/X依存の4件は未実行。
- ヘッドレスGPUブリッジ試験が成功。実Reactビュワーへのネイティブ入力経由のダブルタップ、20テーマ、マウス／タッチ／キーボード操作も単独再実行で成功。作業・ビルド並行中の途中試験では低速ダブルタップ／再生回数の失敗があり、初回からすべて成功したわけではない。
- 一時スナップショットの検証後、`pixvault-frame-*`の一時ディレクトリーが残っていないことを確認。
- 最終の連続検証では通常Rust試験、専用ネイティブ試験、GPUブリッジ、React操作試験、TypeScript、Vite、NSISビルドが成功。生成NSISを必須にした外部起動／関連付け11件も成功（スキップなし）。性能上限は変更せず、起動JS 319.6 KiB／gzip 99.5 KiB、総アセット2634.8 KiBで合格。
- 完成EXEからWindowsマニフェストを抽出し、Windows 10/11互換性、PerMonitorV2、Common Controls宣言を確認。インストーラーの版数・署名状態・SHA-256を検証し、599ファイルを`release/0.4.0`へコピー後にコピー元／先のSHA-256一致を確認。
