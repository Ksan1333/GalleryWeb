# PixVault for Windows アプリ仕様書 v0.4.1

更新日: 2026-09-10。対象: Windows 10/11 x64、DBスキーマ9。以下以外はv0.4.0の仕様を継承する。過去版の成果物・仕様書は残す。

## 音声解析クラッシュの修正

libVLC 3.0.23のamem音声出力はS16N（符号付き16bit、ネイティブエンディアン）。従来のFL32要求は同梱実装で反映されず、PixVaultがf32として倍の長さを読んでいた。9月10日15:26の2件のクラッシュダンプで音声解析中の範囲外読み取りを確認した。

出力要求をS16N／48,000Hz／1chへ明示し、コールバックのcount個のi16を読む。正規化値はsample / 32768。最大384,000サンプル（8秒）まで、NULLや0件は無視する。音声を解析する別プレイヤーはスピーカーへ出力せず、解析終了・失敗・プレイヤー終了時に停止し、停止後に解析用メモリーを解放する。

元動画は変更せず、変換用動画や解析音声ファイルは生成しない。クラッシュダンプやユーザー動画はリリースへ添付しない。

## Windows版の自動音量調整

- 起動は保存済み音量とミュートを使用し、解析中・解析後とも一律50%へ変更しない。
- 解析信号のRMSが0.22以上、またはピーク0.98以上かつRMS 0.12以上を大音量と判定する。0.8秒以上の大音量サンプルで早期決定、それ以外は約4.5秒で決定、解析の失敗や5秒のタイムアウトでは減衰なし。
- 大音量時の減衰率は `min(1, 0.18 / RMS, 0.9 / peak)`。保存音量にこの率を掛け、ネイティブAPIに合わせて1%刻みで切り下げる。一律50%ではない。静かな音声や無音は増幅しない。
- 例: 保存音量80%、RMS 0.4、ピーク0.8なら約36%へ低下する。以降のホイール上げは約41%、下げは約31%になる。
- 減衰はセッション中1回。適用後に遅い保存設定が届いても、下げた値を引き上げない。明示的にスライダー・ホイール等で操作した後は、その実音量を優先し、解析結果や設定復元は上書きしない。
- 表示は下げた実音量。50%への読み替えや、スライダーの裏で別の減衰ゲインを重ねる処理は行わない。通常の手動音量保存は維持し、自動解析値だけで保存設定を上書きしない。
- ミュート／音量0は維持する。判定前には保存音量で再生される短い期間がある。RMS／ピークに基づく簡易調整であり、ライブラリ全体の平均やLUFSに揃える処理ではない。後半だけ音量が大きくなる動画の継続監視は行わない。
- 本変更の自動音量ポリシーはWindowsのlibVLC経路が対象。ブラウザー／Linuxの既存Web Audio経路は変更しない。

## 検証

- Rust標準試験に、i16端点の正確なRMS／ピーク、8秒上限、NULL、音量の実測減衰・静音維持・遅延設定・解析前後の手動操作を追加。
- Windowsの保護ページ直前へ1／1114／2048サンプル（4KiBページ時）を置き、本番コールバックが境界を越えて読まないことを試験する。1114は実クラッシュと同じサンプル数。旧f32読み取りでは保護ページに到達する配置。
- `PIXVAULT_TEST_FFMPEG`へテスト専用FFmpegを指定し、`node scripts/create-vlc-fixtures.mjs --performance`で既存5動画形式、AAC4条件、性能用動画をtarget以下へ生成する。FFmpegは製品へ同梱しない。
- `PIXVAULT_VLC_FIXTURES`へ`src-tauri/target/vlc-fixtures`の絶対パスを設定し、`cargo test --manifest-path src-tauri/Cargo.toml --release --lib vlc_ -- --include-ignored --test-threads=1 --nocapture`を実行する。AAC4条件を各3回解析し、実PCMのRMSも確認する。ネイティブのAAC再生、シーク、一時停止、音量維持、ファイル解放も検証する。
- 実Reactビュワーのヘッドレス試験で、実音量31%の表示、ミュート維持、ホイールで36%→31%、遅い設定の上書き防止を検証する。

## 確認結果

- Rust通常185件、Windowsパス統合1件が成功。libVLC／ネイティブ専用16件も全件成功。通常時に省略する5件のlibVLC試験は専用実行で確認し、外部AI/X依存の4件は未実行。
- メモリー保護境界試験、PCM16の正確なRMS／ピーク、実測に応じた音量減衰、手動優先の試験が成功。AAC4条件×3回の実解析と、AACネイティブ再生・音量・シーク・ファイル解放に成功。
- GPUブリッジ、実React操作と20テーマ、TypeScript、Vite、既存性能上限、ランタイム性能契約に成功。UI試験の初回はホイールイベントの送信先を誤って音量パネルへ指定して失敗したため、実際の操作対象である動画領域へ修正して再実行し成功した。
- 合成1080p60の比較試験では、約7秒のプロセスCPU時間が旧方式0.469秒／ネイティブ0.047秒、CPU画像コピーは旧方式2,936,433,528 bytes／ネイティブ0。Direct3D11／D3D11VAモジュールの読み込みを確認。これは非表示ウィンドウでの計測であり、実画面のFPSやすべての動画の改善率を示すものではない。
- NSISビルド、完成インストーラーの版数・署名状態・SHA-256検証が成功。生成NSISを必須にした外部起動／関連付け11件が全件成功。完成EXEのWindows互換性／PerMonitorV2／Common Controlsマニフェストも確認した。
- 最終性能値は起動JS 319.6 KiB／gzip 99.5 KiB、総アセット2635.3 KiB。既存の上限は変更していない。スナップショット試験後の`pixvault-frame-*`一時ディレクトリー残留なし。
- 配布用599ファイルを`release/0.4.1`へコピーし、元／先のSHA-256一致を確認。旧版は上書きしない。
