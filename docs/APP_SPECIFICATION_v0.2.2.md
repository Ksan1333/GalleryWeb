# PixVault for Windows アプリ仕様書 v0.2.2

- アプリ版数: 0.2.2
- 更新日: 2026-09-04
- 対象: Windows 10 / 11 x64、React / TypeScript + Tauri / Rust
- 配布形式: NSISセットアップEXE
- DBスキーマ: 8（変更なし）

## 1. 起動時の読み込み順序

ホームのお気に入り24件は、全ライブラリの件数集計の完了を待たずに要求する。お気に入り数やカタログ更新時には再検証するが、読み込み済みの棚をローディング表示に置き換えない。任意のUIモジュールは最低750msの猶予を置き、その後のアイドル時間へ遅延する。

件数集計、優先フォルダー一覧、メディア一覧・ページ情報、サムネイル元情報の取得と失敗時照合はblocking workerで実行する。管理済みのDB接続を使用し、要求ごとにDBを再初期化しない。サムネイル索引マニフェストのディスク読み込みとJSON解析も起動の同期処理から分離する。索引の構築中に追加・削除した項目はスナップショットへ重ね、古い索引で上書きしない。索引未完成時も表示項目の個別キャッシュ照会を利用できる。

## 2. サムネイルとギャラリー

ホームの横スクロール棚は共通のIntersectionObserverを使い、画面内に入ったカードだけがサムネイルを要求する。一度表示したカードは横スクロールで戻った際の再読み込みを避けるためマウントを維持する。フォルダープレビューも同じ交差監視を共有する。

サムネイル状態そのものは即時更新し、Reactへの変更通知は1描画フレームにつき各項目1回へ集約する。最初の要求群はmicrotaskでまとめ、完了後の次バッチはイベントループへ制御を返してから開始する。既存の上限（フロント側2バッチ×8件、ネイティブ生成側の1～4ワーカー）は増やさない。大量の既知パスを登録した場合のキャッシュ全件整理をまとめ、購読中・利用中・処理中の項目を整理対象にしない。

ギャラリーの近傍項目はネイティブサムネイルの先読みを継続する。キャッシュ済み画像は画面外でも利用できるが、キャッシュがない項目の原寸画像、動画デコーダー、PDFレンダリング、ZIP表紙展開は画面内に入るまで開始しない。サムネイル解像度、保存画質、元ファイルは変更しない。

64件ページングと仮想スクロールを維持する。追加ページの到着で既存カードの選択コールバックを作り直さず、不要な再描画を避ける。Ctrl・Shiftによる選択は最新のコミット済み読込項目を参照し、未読込範囲の選択は既存の分割読み込みで補完する。ビュワーは全件相当の移動範囲を維持し、22万件をDOMへ一括生成する方式にはしない。

## 3. 全フォルダーと自動同期

ギャラリーとお気に入りの間の「全フォルダー」から、登録なしでWindowsドライブと子フォルダーを閲覧できる。通常は開いた場所の直下を読み込み、優先指定した場所は配下も先に読み込む。優先解除で元ファイル・タグ・お気に入りは削除しない。未閲覧・未優先の全PCファイルを事前索引化する方式ではない。

一覧はウィンドウの残り高さを使用し、名前を含む正方形のコンパクトタイルと仮想スクロールを維持する。全フォルダーの名前は11px・最大2行、長い名前はツールチップで補完する。未集計の子フォルダーに0件バッジを表示しない。狭い画面では移動・パス・更新操作を折り返し、高さ700px以下では補助見出しと説明だけを省略する。

ファイル監視の購読は即開始する。起動・再接続時の全体照合だけを通常変更と別キューに置き、8秒の猶予後、最後の前面操作・要求通知から2秒空いてから1ルートずつ開始する。これは実行中ジョブ数による判定ではない。優先指定の再帰監視ルートを優先する。待機30秒経過後は前面処理が続いていても開始対象にできる。ただし先行ルートの処理時間を含む、全ルートの30秒以内の開始・完了を保証するものではない。

通常の作成・更新・削除通知は従来どおり約400ms単位でまとめて差分照合する。初期照合待機中も通常通知を全件走査へ変換しない。通知欠落・バッファあふれは再照合で補う。不在判定は読み取り可能な親フォルダーで確認し、切断やアクセス不能を一括削除と誤認しない。

## 4. 継続機能とデータ

画像・GIF・動画・PDF・ZIP/CBZ、検索、タグ、年齢区分、お気に入り、OSごみ箱、日・月・年グループ化、ネイティブ全画面、ブックの右綴じ見開き、動画音量保存、削除後の次メディア表示、AI分析、Xダウンロード、設定移行を維持する。

この版はブックのページキャッシュの保存・削除仕様を変更しない。既存のページキャッシュ、サムネイル、DB、元メディアを削除しない。ビルド後のクリーン対象は再生成可能なRustビルド領域のみとし、node_modules、dist、ユーザーデータ、過去版の成果物・仕様書は保持する。

## 5. 検証方法と制限

- `scripts/test-startup-performance.mjs`: 実AppとMediaCollection、モックのネイティブAPI、22万件相当の隔離データを使い、要求順序・画面外要求数・カード再描画・追加ページ・選択操作をヘッドレス検証。`--baseline-0.2.1`で旧ソースとの比較が可能
- `scripts/test-thumbnail-coordinator.mjs`: モックI/Oで通知集約、制御の返却、キャッシュ整理、優先順位、同時実行上限、取消、再試行を検証
- `scripts/test-media-visual-admission.mjs`: 実コンポーネントの抽出コードで、画面外の重いフォールバックを抑え、表示時に全メディア種類の処理を再開できることを検証
- `scripts/test-filesystem-layout.mjs`: 6ウィンドウサイズで全フォルダーのレイアウト、長い名前、240フォルダー末尾、移動、空・エラー状態を回帰検証
- TypeScript、本番ビルド、性能予算、レイアウト、ランタイム性能、20テーマ、全画面・更新経路、Rustテスト、サムネイル性能、NSISメタデータ・SHA-256を確認

これらは隔離したヘッドレス・モック試験であり、利用者の22万件の実ディスクを使った起動時間やFPSの測定ではない。巨大ルートの全体照合は開始後に細分化・中断する実装ではなく、開始後のディスク競合が残る可能性がある。

PC画面操作、画面撮影、可視GUI起動は行わない。Windows実画面での操作感、実ライブラリでの効果、インストーラーGUI実行は未確認。インストーラーは未署名でSmartScreen警告の可能性があり、署名済み自動更新は無効。
